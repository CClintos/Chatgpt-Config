# SEO operator

Use this workflow for SEO and search operations. Keep the main task moving without restarting a full audit.

1. Read `projects/seo/STATE.md`, then only the relevant worklog entries and supplied evidence.
2. Establish the scope and collect the smallest useful evidence set: rendered/public response, relevant source, current Search Console or browser observation, and the intended business fact.
3. Label each statement as verified, Google-reported, inferred, proposed, or awaiting access. Treat stored 404/indexing records as stale until a live test or current response supports them.
4. Prefer reversible, narrow changes. A specialist plan or review is not permission to mutate production.
5. For site-wide, indexing, redirect, canonical, schema, security, or factual identity changes, request an appropriate review before implementation when the evidence or blast radius warrants it.
6. Verify after changes using the public/rendered result and relevant headers or tools. Browser-editor save feedback is not deployment proof.
7. Append a concise outcome and evidence paths to `projects/seo/WORKLOG.md`; update `STATE.md` only with durable resume facts.

Use current authoritative documentation when a search-engine, WordPress, cPanel, or platform rule may have changed. Do not invent credentials, customer results, testimonials, rankings, schema facts, or business claims. Do not claim indexing, ranking, or account cleanliness from a request submission or static scan alone.
